# Development facts request source

Source/owned fixtures only. This is not a native operator packet, selected binary,
device authorization, native authority object or a timing feasibility result.
It implements the fixed publisher and historical result validation for accepted
SDK facts entry proposal `2f6218b1ec6dd9f908cea60cb0700c07848b3458` and reader
`6875514bc498d25457a835accfc7e96e4b28447f`. Exact entry implementation linkage is
recorded in the SDK checkpoint and source-review packet.

The C++ publisher admits one fresh live waiting stage under the pinned mode-0700
directory and nonblocking descriptor lock. It verifies mode-0600 no-follow inputs,
directory dev/inode, nonce/PID/start, executable/payload hashes, maps/environment,
closure/restoration absence and exclusive token publication. It runs no commands,
UI actions or services and spawns no children. Its successful exit means only that
one request file was published; the SDK still independently accepts or refuses it.
Bounded reads/hashes do not guarantee a hard syscall time limit. No general effect
supervisor or setup/open guard is included.

The fixed PowerShell validator checks exact success shape and private nonce/process,
document/order/index, metadata connections, local epoch/interval and authority=false
facts. It does not establish live generation, preservation or completed restoration;
those remain separate duties of a later independently reviewed literal packet.

Owned checks: `test-publisher.sh` builds only a fixture executable, syntax-checks the
publisher CLI, and exercises 19 admission/publication cases. Its `payload.so` is
plain non-ELF data mapped read-only, not a built or executed preload extension.
Loader warnings that this data is ignored are expected. This tests proc/file binding
mechanics only. `test-facts-proof.ps1` tests strict fact/callback acceptance and
refusal locally, including missing/type/identity/order/deadline/authority failures.
The SDK fixture runner can mount this source read-only for an original-QML end-to-end
publisher/request/entry/facts result check. No tablet or native extension is involved.

Main alone chooses a later native build and packet after a supported manual timing
procedure. Keep the 20-second setup, accepted-request plus five-second read, 35-second
