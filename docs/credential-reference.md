# Saved model credential reference

This maintenance entry edits only root `model_credential` in an existing absolute `REMARKABLE_BUDDIES_CONFIG` file. Use `--credential-reference-operation inspect` without input, or prepare/apply/status with exact `--credential-reference-input -`. Requests are strict EOF-delimited UTF8 JSON; request and single-LF report each cap16384 bytes, and Config input/target cap1048576 bytes. No default Config path or input-file fallback is accepted.

Inspect returns the original file/path hashes and reference origin/presence. Prepare supplies `{credential_reference_version:1,operation:UUID,base_sha256,config_path_sha256,change}`. Change is exactly `{action:"set",value:STRING}` or `{action:"clear"}`. Accepted names preserve case and contain1..80 ASCII letters/digits/hyphen/underscore. Clear removes the declaration. Missing clear and the same decoded string are exact byte no-ops; declared-null clear changes the declaration. Invalid whole originals refuse instead of being repaired. Unrelated declarations and values survive.

Changed prepare returns a digest-only intent. Keep the original change privately: apply accepts `{intent,change}`, validates the original file/path/change/target and uses the existing conditional Config writer and current Store-mode custody through consuming output. Status accepts only `{intent}` and observes desired full bytes or unresolved. Names and digest context remain private maintenance input; reports expose only reference origin/presence. Do not place private changes, hashes or intents in renderer state, logs or public examples.

Inspect/prepare/status avoid declared-root, Store and credential-file probes. Apply retains the existing root/ancestor safety metadata checks, including the credentials root, and existing selected-aware Store ownership. It does not initialize or repair storage, discover/read/write credential files or change the credentials root. A complete verified apply confirms saved Config bytes; every operation still reports runtime activation unverified.

A saved reference does not prove a file exists, is protected, is effectively selected or authenticates. Clearing it neither deletes a file nor revokes environment/CLI/active credentials. CLI > environment > protected-file precedence remains unchanged. The separate [credential-file protocol](model-credential.md) retains its own original Config binding and uncertainty. Reference edits can make that binding stale, which does not settle an earlier unknown attempt.

Possible publication/readback failure or incomplete output remains unknown. Do not automatically retry, rebase, roll back or issue a second report. Explicit original-intent status is current-byte observation only. Companion UI, private buffer lifetime and multi-step reference/file setup require their own reviewed sequencing; no atomic two-file setup is promised. The exact protocol and synthetic vectors are in the coordinated central `edit-saved-model-credential-reference` change.
