# Ordinary conversation-root candidates

The Linux `--inspect-conversations` route lists up to sixteen Buddy-owned ordinary
current value-root IDs for explicit selection. It has no input file, stdin body,
filter, nonce or path override. Use the existing explicit absolute
`REMARKABLE_BUDDIES_CONFIG` selector. The command never starts or changes a service.
Recognized execution/override conflicts refuse before startup. Standard parser
diagnostics can echo unexpected argv; keep private values out of unsupported
arguments.

This is payload-reading discovery: it validates/reconstructs owned persisted
envelopes and referenced media under the existing finite recovery/read-work limits.
It is not a metadata-only listing. A large, unsupported, unsafe, selected or
unavailable Store can refuse even when a particular conversation is small.
Existing ordinary absent/LocalOnly mode and a fixed observed inactive Buddy unit
are required. Non-Linux refuses before Config, filesystem or service observation.

The closed version-one JSON report is at most8KiB including newline. Only
`status=complete` has a candidate array and matching count, sorted by canonical
UUID string. A complete empty array means no current supported value-root
candidates under this scope; historical records and deleted roots may still exist.
Singleton tombstoned roots are excluded. Ambiguous root heads, retained type reuse,
unsupported Conversation history or more than sixteen current candidates refuse
without a truncated prefix; refusal array/count are null.
Exit0 means a report was emitted, including refusals; parse its status. Exit1 is
output failure and exit2 is an ordinary command-line parser error.

Candidate presence does not evaluate pending/conflicted descendants, deletion
eligibility, current native bindings or runtime health. Select an ID deliberately,
then use a fresh existing conversation `inspect`/`prepare` and retain its original
intent for any later apply/status. Never treat an inventory report as that intent.
No content, title, source/native identifier, Config path, credential or error text
appears. No physical reclamation, remote deletion or data mutation occurs.

Configuration reads and mode admission keep their independently bounded readers
and fixed schedules. Owned Store recovery and every new typed root decode share
the finite Session meter; no per-root reset or fallback is permitted. Original
Store/mode custody remains held through final output or output failure. Interrupted
deletion orphan objects cannot be adopted without the separate original-intent
status operation. No staging cleanup or repair is performed to make a view fit.

Source/fixture/build results are separate from real-unit, tablet, provider and
native/runtime qualification. Actual early CLI tests stop before the real observer;
controlled models and subprocesses do not establish a qualified on-device flow.
Full normative rules live in the paired central Docs change
`inspect-historical-conversation-candidates`. Future Manager consumption is separate.
