# Ordinary owned archive export

Use `--ordinary-export-operation prepare|apply|status --ordinary-export-input -` with one EOF-delimited strict JSON request. Input and single-LF report each have a16384-byte cap. Prepare/apply require `REMARKABLE_BUDDIES_CONFIG` to select an existing absolute configuration file; there is no default-file fallback. Status does not read that file or open a source Store.

Prepare supplies `{export_version:1,operation:UUID,destination:ABS}`. The parent must already exist, the destination must be absent and outside every owned root through lexical/canonical/case/reparse checks. Only an existing ordinary format1 unconfigured/local-only Store is admitted. No initialization, mode change, selected restore or provider/runtime action occurs. Private intent binds original file/path, actor/mode, generation/full history, raw optional stored snapshot and desired archive bytes. Apply supplies `{destination:ABS,intent:INTENT}` unchanged and refuses changed original conditions.

The producer exclusively reserves a new destination under the same writer mutex and reuses the existing format1 object-copy and backup.json publication path. Source data and any partial destination are retained. Failure before a marker attempt is not-published and can leave a partial directory; marker-attempt/readback or missing output remains unknown. Do not retry, remove output or roll back automatically. A complete verified apply confirms exact marker bytes and promised-object/lineage readback, with runtime activation unverified.

Status uses only `{destination:ABS,intent:INTENT}` and the explicit destination. It can observe desired-archive-observed or unresolved; it grants no historical publisher identity, original apply completion, source Store admission or runtime/native readiness. Intentionally omitted media can remain a valid complete_media:false archive; missing promised included objects cannot be verified. A later refusal does not settle a previous unknown attempt.

Reports contain only fixed counts, booleans, UUIDs and hashes. Archive contents remain private: the optional stored portable Config snapshot can include opaque model/endpoint text and credential-reference metadata. It is not necessarily the current active file and is never installed by export. Credential files, cache files, binaries and native original documents are excluded. Existing selected-export, general/basic/model settings and legacy library contracts remain unchanged. Both-host UI/private-reference lifetime and physical qualification require separate delivery.
